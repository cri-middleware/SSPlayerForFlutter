# 🎯 パーツトラッキング

パーツトラッキングは、指定したパーツに任意の Flutter ウィジェット（武器・エフェクト・当たり判定の目印・
HP バーなど）を毎フレーム追従させる機能です。追従するのは**位置・回転・スケール**です。プレイヤーはそのウィジェットを生成も破棄もせず、姿勢を渡すだけです。子ウィジェットのライフサイクルは通常のウィジェットと同じくユーザーが所有します。

`SpriteStudioPartAnchor` がパーツの姿勢を読み取り、子ウィジェットを `Transform` で包みます。

`SpriteStudioAnimation` の中なら、`children` に置いて `player` は省きます。アンカーがそのウィジェットのプレイヤーを見つけ、`children` はもともとアニメーションと同じボックスを覆います。

```dart
SpriteStudioAnimation.asset(
  'assets/spritestudio/Ringo/Ringo.ssab',
  children: [
    SpriteStudioPartAnchor(partName: 'apple', child: const Icon(Icons.star)),
  ],
)
```

自分で組んだ `SpriteStudioView` に重ねる場合は、そのプレイヤーを渡し、ビューと同じボックスを覆います。

```dart
Stack(
  fit: StackFit.expand,
  children: [
    SpriteStudioView(player: _player),
    Positioned.fill(
      child: SpriteStudioPartAnchor(
        player: _player,
        partName: partName,
        child: const Icon(Icons.star),
      ),
    ),
  ],
)
```

!!! warning "アンカーはビューと同じ座標空間に置く"
    ビューはアニメーションを**自身のボックス**にフィットさせ、そのボックスの中央を基準に配置します。アンカーが読む姿勢にはそのフィットが含まれ、アンカーは**自身の制約**から同じ中央寄せを適用します。両者が一致するのは、アンカーがビューとまったく同じボックスを覆っているときだけです。したがって 1 つの `Stack` の中で `SpriteStudioView` の兄弟として `Positioned.fill` で重ね、位置の微調整やスケールは `Stack` 全体に掛けて両者が一緒に動くようにしてください。異なるボックスを与えると、子ウィジェットはその差の半分だけパーツからずれます。制約が非有限の軸では中央寄せの基準が無いため `0` にフォールバックします。

!!! warning "メッシュ（スキン）パーツには直接追従できません"
    ボーンにバインドされた**メッシュパーツ**（手や顔などの変形パーツ）は、頂点がボーンのスキニングで描かれる一方、パーツ*自身*の変換はセットアップ時のノード位置——多くはキャラクターのルート付近——に留まります。そのため、こうしたパーツを追従先に指定すると、対象は見た目の絵ではなくルート付近に吸い寄せられます。

    メッシュパーツの位置に追従させたいときは、SpriteStudio 側でその位置に **NULL パーツ（ボーンポイント／空パーツ）** を 1 つ置き、そのパーツ名を追従先に指定してください。ボーン（armature）やジョイントパーツを指定しても同様に追従できます。*リジッド*（変形のみ・ボーン無し）のメッシュは正しく追従できるため対象外で、ズレるのはスキンパーツだけです。あるパーツがこれに該当するかは
    `isPartSkinnedMesh(name)` で判定でき、追従先の選択 UI で注意表示・淡色表示に使えます。これは**ヒントに過ぎず**、追従自体を妨げることはありません。

## プロパティ

| プロパティ | 説明 |
|---|---|
| **`player`** | 追従元となるプレイヤー。`SpriteStudioAnimation` の `children` の中では省略でき、そのウィジェットのプレイヤーを使います |
| **`partName`** | 追従対象のパーツ名（`.ssab` の `PartData` 名）。存在しない名前や現在のアニメーションに無いパーツを指定した場合は、解決できるようになるまで何も描画しません |
| **`child`** | パーツに貼り付けるウィジェット。その**左上**がパーツの原点に固定されます |
| **`position`** | パーツの位置を駆動するか。既定 `true` |
| **`rotation`** | パーツの回転を駆動するか。既定 `true` |
| **`scale`** | パーツのスケールを駆動するか。**既定 `false`** — 追従対象はパーツの位置に置くもので、パーツに大きさを決めさせるものではありません。3 つすべて ON のときだけアフィンをそのまま適用するため、パーツの反転が厳密に一致します。姿勢は ON/OFF いずれでも**せん断（Skew）を含みません** — 追従先が追従対象パーツによってせん断されることはありません（SpriteStudio では Skew は子に伝搬しません） |
| **`onHidden`** | パーツが hide のフレームでの挙動。`followAlways`（既定）/ `hideChild` |
| **`onMirrored`** | プレイヤーを反転したときの子ウィジェットの扱い。**`scale: true` のときだけ**効きます。鏡像はスケールの符号なので、`scale` が OFF なら子ウィジェットは鏡像にならず、反転後の角度で正立します。`follow`（既定）/ `cancel` |
| **`filterQuality`** | 任意の `Transform.filterQuality`。回転・拡縮した子を滑らかにしたい場合は `FilterQuality.low` など。null なら Flutter 既定（最近傍）のまま |

### hide フレームでの挙動（`SpriteStudioAnchorHidden`）

| 値 | 挙動 |
|---|---|
| `followAlways`（既定） | hide フラグに関係なく追従を継続し、子ウィジェットを表示し続ける |
| `hideChild` | パーツが hide の間は子ウィジェットを描画しない |

ここでいう hide は、キーフレームの `hide` と表示指定オーバーライドを合成した結果です（[パーツオーバーライド](part-overrides.md) が書き込むのと同じ値）。

### プレイヤーを反転したときの挙動（`SpriteStudioAnchorMirror`）

プレイヤーの [`flipX` / `flipY`](playback.md) はアンカーにもそのまま伝わるので、キャラクターが向きを変えても子ウィジェットはパーツから外れません。決めるのは、**子ウィジェット自身を鏡像にするかどうか**だけで、それも `scale` が ON のときだけです。既定の `scale: false` では子ウィジェットは鏡像にならず、反転後の位置と角度に正立したまま追従します。

| 値 | 挙動 |
|---|---|
| `follow`（既定） | パーツの姿勢をそのまま適用する。プレイヤーが反転していれば子ウィジェットも鏡像になる |
| `cancel` | 反転後の**位置**には追従しつつ、子ウィジェット自身の向きは保つ |

武器やエフェクトのようにキャラクターと一緒に反転してほしいものは `follow`、文字・アイコン・HP バーのように鏡像になると困るものは `cancel` を選んでください。

```dart
SpriteStudioPartAnchor(
  player: _player,
  partName: partName,
  scale: true,                                  // パーツの大きさに合わせつつ…
  onMirrored: SpriteStudioAnchorMirror.cancel, // …名前ラベルは読めるまま
  child: const Text('Player 1'),
)
```

!!! info "`cancel` は厳密で、ズレを残しません"
    取り消しているのは、このライブラリ自身が掛けた ±1 の対角行列だけです。そのため位置は完全に正確なまま、余計な回転も残りません。

    なお、**SpriteStudio 側でパーツ（やその親）に付けられた負のスケールは、どちらを選んでも子ウィジェットに届きます**。それはアニメーションの一部だからです。`cancel` が取り消すのはプレイヤーの
    `flipX` / `flipY` の分だけです。

!!! tip "追従の基準点を変える"
    パーツに乗るのは子ウィジェットの左上です。別の点を合わせたい場合は子側で包んでください。
    `FractionalTranslation(translation: Offset(-0.5, -0.5), child: ...)` とすれば、子の中心がパーツに乗ります。

## ウィジェットを使わずに姿勢を読む

アンカーは `SpriteStudioPlayer` の読み取り API を薄く包んだものです。そのため Flame コンポーネントや
`CustomPainter`、独自のレイアウトコードから、自前でパーツに追従させることもできます。

```dart
// パーツ名の解決は 1 度だけ。パーツインデックスは同じ .ssab 内では安定しています。
final partIndex = _player.findPartIndex(partName);

// そのパーツの現在フレームの姿勢（プレイヤーローカル＝アニメーション空間）。
final Matrix4? pose = _player.partTransformByIndex(partIndex);
if (pose != null && !_player.isPartHiddenByIndex(partIndex)) {
  final x = pose.storage[12];
  final y = pose.storage[13];
  // ... (x, y) に弾を発射する、自前のコンポーネントを配置する、など
}
```

| メソッド | 説明 |
|---|---|
| `findPartIndex(name)` | パーツインデックス。パックに無ければ `-1` |
| `partNames` | パーツ名一覧 / 名前⇔インデックスの相互解決（`PartNameTable`） |
| `partTransform(name)` | 直前の tick で組み立てたフレームでの、そのパーツの変換行列を `Matrix4?` で返す（プレイヤーローカル）。`load()` 前・アニメ選択前・不明なパーツでは null |
| `partTransformByIndex(index)` | `partTransform` のインデックス指定版（名前解決を省略） |
| `isPartHidden(name)` | 直前の tick で組み立てたフレームで、そのパーツが hide かを返す。`load()` 前や不明なパーツでは `false` |
| `isPartHiddenByIndex(index)` | `isPartHidden` のインデックス指定版 |
| `isPartSkinnedMesh(name)` | そのパーツがボーンバインドされた（スキン）メッシュか＝**追従に向かないパーツ**かを返す（上記の警告を参照）。`load()` 前・不明なパーツ・リジッドメッシュでは `false` |
| `isPartSkinnedMeshByIndex(index)` | `isPartSkinnedMesh` のインデックス指定版 |
| `partQuad(name)` | 直前の tick で組み立てたフレームで、そのパーツが描かれている輪郭を `SsPartQuad?` で返す（[後述](#パーツの輪郭)）。`load()` 前・アニメ選択前・不明なパーツ・hide のパーツ・自分では何も描かないパーツでは null |
| `partQuadByIndex(index)` | `partQuad` のインデックス指定版 |
| `hitTestPart(point, {parts})` | `parts` に名前を挙げたパーツ（省略時はすべて）のうち、輪郭が `point` を含む一番手前のパーツのインデックス。無ければ `-1` |
| `hitTestPartByIndex(point, {parts})` | `parts` をインデックスで渡す `hitTestPart` |

!!! tip "一瞬だけ知りたいならアンカーは不要です"
    常時追従させるまでもなく「その瞬間のパーツ位置だけ知りたい」場合（弾の発射位置を取るなど）は、`SpriteStudioPartAnchor` を配置せず `partTransform()` を直接呼ぶ方が簡潔です。

### 行列が持つ情報

返される `Matrix4` が保持するのは **2D アフィンの 6 項（`m0, m1, m4, m5, m12, m13`）だけ**で、
Z / W 行は単位行列のままです。これにより、余計な Z スケールや透視項が `Transform` に紛れ込むことはありません。位置・回転・スケールはすべてこの 6 項に含まれるため、行列はそのまま
`Transform` ウィジェットに渡せます。平行移動成分は `storage[12]` / `storage[13]` です。

姿勢は**せん断（Skew）を含みません**。ランタイムは Skew を「子に伝搬しないローカル頂点変形」として適用します——行列ではなくパーツ自身のクアッドを歪めるため、Skew はワールド行列に届かず、追従先が追従対象パーツによってせん断されることはありません。これは SpriteStudio の仕様（Skew は子に伝搬しない）と一致します。

Y-Down の反転は**ランタイム側で適用済み**です。呼び出し側で再度反転しないでください。

プレイヤーの [`flipX` / `flipY` / `offset`](playback.md) も適用済みです。つまりこの行列は**実際に描かれている姿勢**であり、追従先は反転しても絵の上のパーツから外れません。

### 鏡像（反射）になることがあります

返される行列は**反射**——行列式が負の行列——になることがあります。原因は 2 つあり、しかも**掛け合わさります**。

- SpriteStudio 側でパーツやその親に負のスケールが付いている（実データでは珍しくありません）
- プレイヤーの [`flipX` / `flipY`](playback.md)

2 つが重なると**打ち消し合って**行列式は正に戻ります。したがって「`flipX` したから鏡像」とも「反転させていないから鏡像ではない」とも言えません。符号が必要なときは、そのとき手にしている行列から
`determinant()` で読み取ってください。

!!! tip "すべての軸を追従するときは分解しません"
    `position`・`rotation`・`scale` がすべて ON なら、姿勢は `Matrix4` のまま `Transform` ウィジェットへ渡るため、鏡像も欠落なく運ばれます。どれかが OFF なら、アンカーは追従する軸から姿勢を組み直します。そのとき、子ウィジェットが裏返らないよう、先にプレイヤーの反転を取り除きます。

    ただし**自分で分解する場合**、鏡像の行列から取り出した回転は一意に決まりません（水平反転で 180 度の差が残ります）。行列から回転角を取り出すようなコードを書くときは、先に `determinant()` の符号を確認してください。平行移動成分（`storage[12]` / `storage[13]`）は符号に関係なく常に正確です。

### パーツの輪郭

`partQuad` は `SsPartQuad` を返します。パーツが描かれている 4 隅（`leftTop` / `rightTop` / `leftBottom` / `rightBottom`）を `partTransform` と同じ座標で持ち、`bounds`（4 隅を囲む軸平行の矩形）と `contains(point)` を備えます。`SpriteStudioView` の上では、ビュー自身の座標の点からビューの箱の中心を引くとこの座標になります。

```dart
// `local` はビューの座標の点、`size` はビューの大きさ
final index = _player.hitTestPart(local - size.center(Offset.zero), parts: ['button']);
```

輪郭は描かれているとおりです。セルを持つパーツは描かれている 4 隅で、スキューと頂点変形も入ります。回転したパーツなら回転した四角形になります。Mesh パーツは頂点を囲む軸平行の矩形で、ボーンにバインドされていても描かれている位置になります。Shape はサイズをピボットの周りに取った矩形です。Null・ボーン・Instance・Effect のパーツは自分では何も描かないので輪郭を持たず、hide のパーツも持ちません。アルファ 0 で描かれているパーツは輪郭を持ちます。

!!! note "低レベル API にも同じ読み取りがあります"
    `SpriteStudioPlayer` の下にある描画エンジン `SpriteStudioInternalPlayer` にも同じ読み取りがあります。ヘッドレス実行や独自の描画アダプタから使う場合は、[プレイヤーの構成](../development/architecture.md#driving-l2-directly)を参照してください。

## 追従のタイミングと精度

読み取りは**直前の tick で組み立てたフレーム**を返します。描画パスが描くフレームと同じもの（サブフレーム補間が有効なら小数、無効なら切り捨て）なので、姿勢は常に画面上の絵と一致します。描画との順序を自前で制御する必要はありません。読み取りはフレームを自分では組み立てないので、描画のコストも増えません。オーバーライドは次の tick から、描画と同時に読み取りにも反映されます。一時停止中の `SpriteStudioPlayer` は、そのために次のフレームで 0 秒の tick を 1 回だけ実行します。

パーツオーバーライドと違い、これらは**純粋な読み取りでリスナーへ通知しません**（何も変更していないため）。プレイヤーのリスナーから駆動して、フレームの変換が確定した advance 直後に読み直すようにしてください。`SpriteStudioPartAnchor` は内部でこれを行っているので、ビューが再描画するのと同じ通知でリビルドされ、同じフレームに乗ります。

`load()` の完了前やアニメの選択前に姿勢を問い合わせることは**エラーではありません**。オーバーライドと同様、例外を投げず `null` / `false` を返すため、パックのロード中に動く UI でもガードは不要です。

## 注意点

- **存在しないパーツ名では、`onHidden` の設定に関係なく何も描画されません。** `followAlways` /
  `hideChild` が決めるのは、実在してそのフレームで hide になっているパーツの扱いだけです。
- **そのフレームに存在しないパーツ**は hide では*ない*と読まれます（ワールド変換自体は有効なため）。
- パーツ名は、そのプレイヤー自身が再生しているアニメーションのパーツから解決されます。**インスタンスパーツの内部（子アニメーション）のパーツは追従できません**（子は別のプレイヤーとして動作するため）。インスタンスパーツ自体は追従できます。
- **ボーンバインドされた（スキン）メッシュパーツは、見た目の絵の上には追従できません** —— 代わりにその位置へ置いた NULL / ボーンポイントパーツを追従先にしてください。`isPartSkinnedMesh` は該当パーツを（追従を妨げずに）判定できます。理由は冒頭の警告を参照してください。
- 同名のパーツが複数ある場合は、**最初**に見つかったものが使われます（SpriteStudio はパーツ名の一意性を保証しません）。
- 名前は読み取りのたびに解決し直されるため、**アニメーションの切り替えや別の `.ssab` の読み込みでも登録し直す必要はありません**。名前が解決でき次第、アンカーは再びそのパーツを掴みます。
- 追従で転送されるのは**空間的な変換だけで、描画順は含みません**。子ウィジェットはアニメーション全体の手前に描画され、キャラクター自身のパーツの間に挟み込むことはできません。
- **所有権はユーザー側にあります。** アンカーは子ウィジェットもプレイヤーも生成・破棄せず、姿勢を読んで適用するだけです。

## Flame から使う

`ssplayer_flame` にこの機能の専用 API はなく、`SpriteStudioPartAnchor` はウィジェットなので Flame のコンポーネントツリーの中では使えません。コンポーネントが公開するプレイヤーから姿勢を読み、自前のコンポーネントを駆動してください。

```dart
final player = component.player!;
final pose = player.partTransform(partName);
if (pose != null && !player.isPartHidden(partName)) {
  marker.position = Vector2(pose.storage[12], pose.storage[13]);
}
```

姿勢は**プレイヤーローカル**（アニメーション空間）なので、`SpriteStudioComponent` 自体を配置したのと同じ要領で、自分のコンポーネントの空間へ変換してください。
